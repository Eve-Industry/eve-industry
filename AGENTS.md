# AGENTS.md

Guide for engineers and AI agents working on Eve Industrialist. Read this before changing code.

## What this is

A Laravel 12 monolith for EVE Online industrialists. Players sign in with EVE SSO, link characters, and use planning and tracking tools built on their ESI data plus public market data: manufacturing, reaction and invention calculators, build programs, assets, blueprints, planetary industry, market trading, contract appraisal, a wormhole mapper, moon scans and corporation tools (donations, projects, ESS tracker, structure timers). Admins log in with email/password and manage users, sponsors, settings and a Discord welcome bot.

Stack: PHP 8.2+, Laravel 12, MySQL 8, Redis (cache, sessions, queues), Laravel Horizon, Socialite with the EVE Online provider. Server-rendered Blade views, being replaced page by page by a React app in `frontend/` (Vite, TypeScript) served at `/app` (see `docs/phase-d.md`).

`README.md` is accurate for setup but describes only the original login system. The other root `*.md` files (`IMPLEMENTATION_SUMMARY.md`, `PR_CHANGES.md`, `LAYOUT_GUIDE.md`, etc.) are old PR notes, not current docs.

## Layout

| Path | Contents |
|------|----------|
| `routes/web.php` | All ~200 routes. About 110 are JSON endpoints under `/api` called by Blade pages using the session cookie. Middleware groups: `guest`, `auth`, `stock-manager`, and `/admin` (`auth` + `admin`). |
| `routes/api.php` | Versioned JSON API at `/api/v1` (`auth:sanctum`, same-origin session cookies; only `GET /health` is public). Responses use `App\Http\Responses\ApiResponse` (`{data, meta}`) and resources in `app/Http/Resources/V1`; errors get a `code` (see `bootstrap/app.php`). The OpenAPI spec `docs/openapi.json` is generated by Scramble and checked in CI: after changing the API run `DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan scramble:export` and commit it. |
| `routes/console.php` | Every scheduled task. |
| `app/Http/Controllers` | One thin controller per feature page. `Concerns/ResolvesCorporation` is shared by corp tools. |
| `app/Services` | All business logic and all outside API calls. `EsiService` is the hub for ESI calls, token refresh, error-limit tracking and caching. `EsiRateLimiter` coordinates shared floating token budgets by the pinned route specification and response headers. `EsiHttpCache` preserves source freshness and validators. |
| `app/Console/Commands` | Artisan commands; most are scheduled. Manual tools: `admin:reset`, `queue:clear-batches`, `discord:bot`, `market:sweep-status`. |
| `app/Jobs` | Queued jobs. Commands fan out work per user, per region or per chunk. |
| `app/Models`, `database/migrations` | User data (users, characters, plans, build programs), static game data from the SDE (`eve_types`, `blueprint_activities`, `sde_*`, `inv_*`, `type_materials`, `market_groups`) and market data (`market_prices`, `market_orders`, `market_order_sweeps`, `market_aggregates`, `market_history`, `public_contracts`, `manufacturing_costs`). |
| `config/horizon.php` | Queue supervisors. |
| `tests/Unit`, `tests/Feature` | PHPUnit tests. Unit tests are named after the service or job they cover. |
| `frontend/` | React app (installable PWA, see `docs/pwa.md`; Vite, React 19, strict TypeScript, React Router, TanStack Query). Builds to `public/app` (gitignored), served by `SpaController` at `/app/{path?}` behind `auth`. Its API client is typed from `docs/openapi.json`: after regenerating the spec run `npm run gen:api` and commit `src/api/schema.d.ts`. CI runs type check, build, Vitest and size-limit. When a page moves here, delete its Blade view, its old `/api` alias and that alias's `tests/Feature/LegacyApi` test. |

Request flow: route → controller → service → MySQL / Redis cache / external API. Background work fills tables and cache keys that the request path reads.

Market prices for calculators come from `MarketService::getSellPrices()`: a 5th-percentile average of sell orders, read from `market_aggregates` (the region's last complete order sweep, cached per sweep) or from raw `market_orders` for a region never swept, falling back to `market_prices`. Region order sweeps are run by `MarketOrderSweepService` (see `docs/phase-c.md`). The five trade regions are in `MarketTradingService::REGIONS` (Jita, Amarr, Dodixie, Rens, Hek).

## External data sources

- EVE ESI (`esi.evetech.net`): character, corp, market and universe data. Always go through `EsiService`.
- CCP SDE JSONL zip (`developers.eveonline.com`): static data, via `SdeImportService`.
- Fuzzwork blueprint API: blueprint/reaction activities.
- everef.net: daily market history CSVs and public contract snapshots.
- Discord gateway: welcome bot (work in progress, hidden by default).

## Scheduled tasks

Defined in `routes/console.php`. Times are UTC. Every entry uses `withoutOverlapping()->onOneServer()`. Production needs a cron running `php artisan schedule:run` every minute (see README, Laravel Forge).

|---------|----------|--------|--------------|--------|
| `sde:import` | daily 02:00 | on | Downloads the SDE zip and imports systems, categories, groups, types, market groups, stations, stargates, type materials, blueprints. Skips if checksum unchanged. Inline. | `eve_types`, `sde_*`, `inv_*`, `type_materials`, `market_groups`, `blueprint_activities` |
| `market:update-prices` | daily 04:00 | on | ESI global prices. Inline. | `market_prices` |
| `esi:import-types` | weekly Sun 03:00 | on | Dispatches `ProcessEveTypeChunk` (`updates`). | `eve_types` |
| `sde:import-blueprints` | weekly Sun 05:00 | on | Fuzzwork data, dispatches `ProcessBlueprintDataChunk` (`updates`). | `blueprint_activities` |
| `esi:import-market-groups` | 1st and 15th 03:00 | on | ESI market group tree. Inline. | `market_groups` |
| `characters:refresh-data` | every 30 min | on | Staggered `RefreshCharacterProfile` jobs for recently active users and ESI-active characters. | `characters` |
| `dashboard:refresh` | every 15 min | on | `RefreshDashboardStats` per user active in 7 days, spread over 600 s. Cache TTL 1200 s. | cache `dashboard.*` |
| `industry:refresh` | every 30 min | on | `RefreshIndustryData` per active user. | cache (IndustryService) |
| `assets:refresh` | every 30 min | on | `RefreshAssetData` per user active in 7 days with an ESI-active character. | SQL owner snapshots (optional legacy cache dual write) |
| `market:import-daily-history` | every 3 h | on | `ImportDailyMarketHistory` (`updates`) for today and yesterday from everef. | `market_history` |
| `contracts:import` | hourly | on | `ImportPublicContracts` stages a generation and atomically publishes its pointer. | `public_contracts`, `public_contract_items` |
| `market:fetch-region-orders --region=10000002` | every 15 min, gated | on | Jita sweep: `FetchRegionOrders` → `FetchRegionOrderPages` batch → `CompleteMarketOrderSweep` (`market`). Runs every 15 min while the last complete sweep took < 10 min, else every 30 (`MarketOrderSweepService::isDue`). | `market_orders`, `market_order_sweeps`, `market_aggregates` |
| `market:fetch-region-orders --exclude=10000002` | hourly | on | Same sweep for Amarr, Dodixie, Rens and Hek. | same |
| `manufacturing:precompute-costs` | every 4 h | on | Safety net: `PrecomputeManufacturingCostsChunk` (`updates`) per trade region, ME 0–10. A completed sweep also queues it for its region (at most every 30 min). | `manufacturing_costs` |

| `esi:diagnostics-prune` | daily 06:30 | on | Deletes expired diagnostics rows in 500-row batches (events 14 d, endpoint metrics 90 d, budget minute rows 7 d, hourly 90 d). | same |
| `demo:reset` | daily 03:30 | on, no-op unless `DEMO_ENABLED` | Regenerates the demo account with three new characters and warms its caches. See `docs/demo-mode.md`. | demo user rows, `characters`, asset snapshots |

| `market:fetch-region-history` | every 6 h | off | `FetchRegionHistory` → `FetchRegionHistoryChunk`. Replaced by the everef import. | `market_history` |

## Queues and workers

- Horizon runs three Redis supervisors: `supervisor-1` on `default` via the `redis` connection (timeout 60 s, 1 try, 128 MB, recycles hourly or after 500 jobs), `supervisor-2` on `updates` via `redis-long` (timeout 600 s, 3 tries, 256 MB, recycles hourly or after 250 jobs) and `supervisor-3` on `market` via `redis-market` (timeout 300 s, 3 tries, 256 MB, recycles hourly or after 1000 jobs). Production runs at most 5 processes: default 1–2, market 1–2, updates 1.
- `config/queue.php` sets `retry_after` to 240 s on `redis`, 960 s on `redis-long` and 420 s on `redis-market`. All use the same Redis database, so jobs dispatch normally with `onQueue('updates')` / `onQueue('market')`; the worker's connection decides `retry_after`. `tests/Unit/JobTimeoutTest.php` fails if a job's `$timeout` is not at least 30 s under its queue's `retry_after`, or if Horizon exceeds 5 processes in any environment.
- Per-user refresh jobs use `default`. Region order sweeps (`FetchRegionOrders`, `FetchRegionOrderPages`, `CompleteMarketOrderSweep`) use `market`. Imports and manufacturing precompute use `updates`. Job `$timeout` / `$tries` override supervisor values.
- Redis has two roles: the `default` connection (queues, Horizon, cache locks; run with `noeviction`) and the `cache` connection (disposable cache; `allkeys-lru`), which uses `REDIS_CACHE_HOST` when set and otherwise database 1 on `REDIS_HOST`.
- Sessions use the non-evicting Redis through the `sessions` connection (database 2 by default). See `docs/operations/esi-scaling.md` for rollout and encryption requirements.
- ESI-calling jobs check `EsiService::isEsiErrorLimited()` and release themselves until the error window resets.
- Horizon dashboard: `/horizon`, admin users only (`HorizonServiceProvider`).
- Long-running processes: `php artisan horizon` and `php artisan discord:bot` (work in progress: exits unless `features.discord_bot` is set to `true` in `config/features.php`, which has no env var, and then unless enabled in Admin → Discord Bot; no daemon for it is defined in the repo).

## ESI diagnostics

Passive, flag-gated capture of ESI traffic (`app/Services/Esi/Diagnostics`), buffered on a Redis stream, drained to MySQL by `esi:diagnostics-flush`, reported at Admin → ESI Diagnostics (`/api/v1/admin/esi-diagnostics/*`). Any code that calls ESI outside `EsiHttpClient` must report its attempts through `EsiDiagnosticsRecorder`; wrap batch calls in `EsiDiagnosticsContext::with()` for dataset, page and batch fingerprint. Rollout, flags and interpretation: `docs/operations/esi-diagnostics.md`.

## Known issues

- Jita sweep timing has not been measured against real ESI; `php artisan market:sweep-status` shows each hub's last sweep and duration, and the Jita cadence drops to 30 min on its own when a sweep takes 10 min or more.
- `sde:import` overlaps with `esi:import-types`, `esi:import-market-groups` and `sde:import-blueprints`, which write the same tables from other sources.
- Deploy paths: README targets Forge (cron + Horizon). `docker/start.sh` takes `APP_ROLE=web|worker|scheduler|migrate` so one image (`Dockerfile.app`) runs nginx/FPM, Horizon, the scheduler or a one-off migration. `docker-compose.yml` is that role split (a `migrate` service the others wait for, two Redis roles); the bind-mounted dev setup is `docker-compose.dev.yml`. No long-running role migrates. After a deploy run `docker/smoke-test.sh BASE_URL` (checks `/up`, `/api/v1/health`, `/api/v1/me` → 401).
- `.github/workflows/ci.yml` runs `php artisan test` on PRs. Local V2 baseline and scaling-branch suites pass with the test APP_KEY; keep external Redis concurrency checks separate from the default SQLite suite. `main.yml` is an unused Copilot setup step.

## Working rules

1. Put logic in a service; keep controllers thin. Add a unit test in `tests/Unit` named after the service, and a feature test in `tests/Feature` for routes or commands.
2. Run tests with `php artisan test` (or `vendor/bin/phpunit`). `phpunit.xml` uses in-memory SQLite, the array cache and the sync queue, so no MySQL or Redis is needed. Format with `vendor/bin/pint`.
3. All ESI calls go through `EsiService` so they are rate-limited, error-limit tracked and cached. Never call ESI directly from a controller or job.
4. New recurring work: add a command, schedule it in `routes/console.php` with `withoutOverlapping()->onOneServer()`, and fan out to jobs with explicit `$timeout`, `$tries` and queue. Limit per-user refreshes to users active in the last 7 days.
5. Bulk writes use chunked `upsert()`. `upsert()` bypasses Eloquent casts, so `json_encode` JSON columns first.
6. Schema changes are new dated migrations; never edit existing ones.
7. Work on a branch and merge to `master` by pull request.
8. Do not add AI attribution (no `Co-Authored-By: Claude`, no "Generated with Claude Code") to commit messages or PR descriptions.

## Open-source release additions

- **Licence:** AGPL-3.0-or-later, provided as is (`LICENSE`, `NOTICE`). The app shows a source link (`APP_SOURCE_URL`, exposed as `source_url` on `/api/v1/me`). Contributions are signed off (DCO). No tracking or analytics on by default, no account impersonation (a CI step fails if the word returns).
- **Self-hosting:** `deploy/` holds the end-user stack (`docker-compose.yml` with Caddy, `.env.example`, `install.sh`/`install.ps1`, `update.sh`/`update.ps1` (refresh the stack files except `.env`, pull all images, restart), `backup.sh`, `restore.sh`); `docs/self-hosting/` explains it. The root `docker-compose.yml` builds from source. `Dockerfile.app` runs as `www-data`; `APP_ROLE` adds `install` (`php artisan app:install`: idempotent admin creation and first game-data import; prints a generated admin password once). Admin settings are read through `config('install.super_admin.*')`, never `env()`. `SetupStatusService` feeds `setup` in `/api/v1/health`.
- **Release:** tag `vX.Y.Z` runs `.github/workflows/release.yml` (multi-arch image to GHCR, Trivy, cosign). `ci.yml` also runs gitleaks and boots the `deploy/` stack.
- **Logging:** `config/logging.php` defaults to the `daily` channel, `LOG_DAILY_DAYS=5`.
- **Themes:** `APP_THEME` selects `public/themes/<name>/theme.css` (or `public/themes-custom/<name>/`, the mounted `./themes`); `ThemeService` injects it into the SPA shell and the Blade layout. Tokens only, no raw colours: `docs/styling.md`.
